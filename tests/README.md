# tests — тесты бэкенда

Покрытие серверной части проекта. Раннер — **встроенный `node:test`** (Node 18+),
никаких внешних зависимостей и сборки, в духе остального проекта.

## Запуск

```bash
npm test                       # весь набор
node --test "tests/*.test.js"  # то же самое напрямую
node --test tests/store.test.js  # один файл
```

## Файлы

| Файл | Что проверяет |
|------|---------------|
| [helpers.js](helpers.js) | Общие утилиты: изоляция данных, запуск сервера на случайном порту, HTTP-клиент с cookie-jar, подписка на SSE. **Не тест** — подключается первым. |
| [auth.test.js](auth.test.js) | `server/auth.js`: хеш/проверка пароля, куки, валидация имени/пароля, роли (env `GOB_GM_USERNAMES`), сессии, `requireAuth`/`requireGameMaster`. |
| [store.test.js](store.test.js) | `server/store.js`: CRUD пользователей/сессий/персонажей/листов, отряды и связи char↔group, инвайты, сообщения, сессия мастера, каскадное `deleteUser`, устойчивость к битому JSON. |
| [server.test.js](server.test.js) | HTTP-API `server/server.js`: аутентификация, персонажи, листы с rev-локами и живой синхронизацией по SSE, группы, инвайты, стол мастера и посылки-предметы, статические страницы. |

## Как устроена изоляция

`helpers.js` при загрузке выставляет `process.env.GOB_DATA_DIR` в уникальную временную
папку (`os.tmpdir()/gob-tests/<pid>-<uuid>`) — **до** того, как загрузится `server/store.js`
(store читает переменную на этапе `require`). Поэтому тесты никогда не пишут в реальные
`server/data/`. Между тестами `resetData()` очищает эту папку (store читает файлы заново,
in-memory-состояния нет), в конце `cleanup()` удаляет её целиком.

Для интеграционных тестов приложение поднимается через `require('../server/server')`
(экспортирует `app`) и `app.listen(0)` — на случайном свободном порту. При обычном запуске
(`node server/server.js`) сервер по-прежнему слушает порт 3000 (`require.main === module`).

## Заметки

- Роль GameMaster в тестах выдаётся через env `GOB_GM_USERNAMES` (роль резолвится в рантайме,
  не на этапе регистрации).
- Тест «усаживание за стол» **характеризует баг B1** ([../docs/BUGS.md](../docs/BUGS.md)):
  `gmUserId` не сохраняется, поэтому `isActiveGm` всегда `false`. Когда B1 починят, тест
  напомнит обновить ожидание.
- Фронтенд (`public/js/*`) здесь не покрыт: модули завязаны на `window`/`localStorage`/DOM,
  для их тестирования понадобится jsdom/happy-dom — это отдельная задача.
