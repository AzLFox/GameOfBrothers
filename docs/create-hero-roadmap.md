# Create Hero — roadmap создания карточки персонажа

**Ветка:** `create-hero`  
**Цель:** рабочий поток «Новый персонаж» → карточка в карусели → лист персонажа с возможностью дозаполнить всё позже.

## Принципы

- Поля **не обязательны**: можно создать полностью пустую карточку одной кнопкой.
- Пустые значения по умолчанию:
  - **Имя** — пустая строка (в UI карточки/листа показывать «Без имени»).
  - **Краткое описание** — пустая строка (на обороте карточки — «Описание не задано» или пустой абзац).
  - **Изображение** — **заглушка** (`/img/char-placeholder.jpg` или SVG), не блокирует создание.
- Всё можно отредактировать позже на странице персонажа (`char-name`, `char-desc`, портрет — отдельная фаза).
- Встроенные герои из `public/data/characters.json` **не перезаписывать** — пользовательские карточки хранятся отдельно и **мержатся** на клиенте.
- Стек без смены: HTML/CSS/JS, `GobMotion`, существующие токены и art-слой.
- Desktop не ломать; mobile — через `GobMobile` / `@media (max-width: 640px)` (база уже в M8).

## Рекомендуемый размер изображения (показать в форме)

| Параметр | Значение |
|----------|----------|
| Соотношение сторон | **3∶4** (как портрет на листе и лицо карточки) |
| Рекомендуемый размер | **600×800 px** (минимум 300×400) |
| Форматы | JPEG, PNG, WebP |
| Макс. размер файла | **2 МБ** (после сжатия на клиенте — цель ≤ 300 КБ в хранилище) |
| Обрезка | Опциональный crop-preview в форме; при несовпадении пропорций — `object-fit: cover` |

Текст-подсказка в UI (пример):

> Загрузите портрет **600×800 px** (3∶4). Если не загрузите — будет стандартная заглушка; картинку можно сменить позже на листе персонажа.

## Модель данных

### Запись каталога (карусель + метаданные)

```json
{
  "id": "u_abc123",
  "name": "",
  "description": "",
  "portrait": "",
  "isUser": true,
  "createdAt": "2026-06-19T12:00:00.000Z"
}
```

- `id` — префикс `u_` + `crypto.randomUUID()` (или короткий uid).
- `portrait` — data URL (сжатый) или пустая строка → заглушка.
- `name` / `description` — дублируют то, что видно на карточке; синхронизируются с листом при сохранении.

### Хранилище (клиент, фаза 1)

| Ключ | Содержимое |
|------|------------|
| `gob-user-characters` | `CharacterCard[]` — массив пользовательских карточек |
| `gob_character_{id}` | существующий JSON листа (`defaultSheet` + правки) |

Серверный `POST` — опционально в фазе C7; до этого всё работает offline-first в `localStorage`.

### Заглушка портрета

- Файл: `public/img/char-placeholder.jpg` (или `.svg`).
- Использовать везде единый хелпер: `getPortraitUrl(card) → card.portrait || PLACEHOLDER`.

## Фаза C1 — Каталог и merge на главной

**Промпт:**
> Реализуй клиентский каталог пользовательских персонажей:
> 1. Создай `public/js/gob-characters.js` — API: `loadAllCharacters()`, `loadUserCharacters()`, `saveUserCharacters()`, `findCharacterById(id)`, `PLACEHOLDER_PORTRAIT`.
> 2. `loadAllCharacters()` — `fetch('/api/characters')` + merge с `localStorage.gob-user-characters` (user в конец или в начало — зафиксировать в комментарии).
> 3. В `index.js` замени прямой `fetch` на `loadAllCharacters()`; для `card-front` и текста на обороте используй `getPortraitUrl(char)` и fallback-имя «Без имени».
> 4. Добавь `public/img/char-placeholder.jpg` (или svg) — нейтральный силуэт в стиле GoB.
> 5. Не менять URL встроенных героев (`/characters/001.jpg` и т.д.).

**Критерии готовности:**
- [x] Главная по-прежнему показывает встроенных героев
- [x] Есть единый модуль каталога, готовый к записи user-карточек
- [x] Заглушка отображается, если `portrait` пустой

## Фаза C2 — Форма создания (UI)

**Промпт:**
> Доведи `/create` до рабочей формы (поля опциональны):
> 1. `create.html`: поля с `id` — `#create-name`, `#create-desc`, блок загрузки `#create-portrait` (input file + preview + hint с размером **600×800, 3∶4, до 2 МБ**).
> 2. Две кнопки: **«Создать героя»** (с учётом заполненных полей) и **«Пустая карточка»** (сразу без полей).
> 3. `create.css`: зона preview 3∶4, dashed border, кнопка «Убрать фото», mobile full-width (M8).
> 4. Подсказка под полями: «Все поля необязательны — можно заполнить на листе персонажа».
> 5. Убрать `disabled` с submit; убрать или заменить заглушечный `create-lead`.

**Критерии готовности:**
- [x] В форме виден рекомендуемый размер изображения
- [x] Preview портрета до сохранения
- [x] Можно отправить форму с пустыми полями
- [x] Визуально в стиле index/character (gob-art, tokens)

## Фаза C3 — Сохранение и переход на лист

**Промпт:**
> Реализуй создание карточки в `create.js`:
> 1. `createCharacter({ name, description, portraitFile })` в `gob-characters.js`:
>    - сгенерировать `id` (`u_` + uuid);
>    - `name` / `description` — trim, допускается `''`;
>    - если файл не выбран — `portrait: ''`;
>    - если файл есть — прочитать, опционально сжать (canvas, max сторона 800px, JPEG q≈0.82), сохранить data URL в `portrait`;
>    - push в `gob-user-characters`;
>    - создать начальный `gob-sheet-{id}` через `defaultSheet(card)` (статы по умолчанию, пустые слоты).
> 2. После успеха — `GobMotion.navigateTo('/character?id=' + id)` (portal-wipe).
> 3. Обработка ошибок: файл > 2 МБ, не-image — сообщение под полем, без alert().
> 4. Кнопка «Пустая карточка» вызывает `createCharacter({})` без валидации.

**Критерии готовности:**
- [x] Создание пустой карточки → переход на лист с заглушкой
- [x] Создание с именем/описанием/фото → те же данные на листе
- [x] Новая запись появляется в `localStorage`
- [x] Навигация назад с create по-прежнему через portal-wipe

## Фаза C4 — Лист персонажа: портрет и пустые значения

**Промпт:**
> Подключи пользовательские карточки к `character.js`:
> 1. Загрузка: `findCharacterById` из встроенных **или** user-каталога; если не найден — экран ошибки.
> 2. `#char-img`: `src = getPortraitUrl(char)`; `alt` из `sheet.name || char.name || 'Без имени'`.
> 3. `renderSheet` / `bindField`: пустое имя на листе допустимо; placeholder в input «Без имени» только как `placeholder`, не как значение.
> 4. При `input` на `char-name` / `char-desc` — если `char.isUser`, обновлять запись в `gob-user-characters` (debounce 400ms, вместе с `scheduleSave`).
> 5. `document.title` — `GoB — ${sheet.name || 'Без имени'}`.

**Критерии готовности:**
- [ ] Лист открывается для `?id=u_…`
- [ ] Пустой герой: заглушка на портрете, пустые поля, лист редактируется
- [ ] Правки имени/описания на листе отражаются в user-каталоге
- [ ] Встроенные герои (001–006) работают как раньше

## Фаза C5 — Карусель после создания

**Промпт:**
> Новая карточка на главной после create:
> 1. При возврате на `/` карусель строится из `loadAllCharacters()` — user-карточки в списке.
> 2. Лицо карточки: `getPortraitUrl(char)`; оборот: имя или «Без имени», описание или «Описание не задано».
> 3. Ссылка «Открыть» → `/character?id={id}`.
> 4. Опционально: query `?highlight={id}` — после create редирект на `/?highlight=u_xxx` и мягкий scroll/rotate карусели к новой карточке (GSAP, уважать reduced-motion).
> 5. Skeleton/intro не ломать при N+1 карточках.

**Критерии готовности:**
- [ ] После create и возврата на главную карточка видна в карусели
- [ ] Кастомный портрет / заглушка на лице карточки
- [ ] Flip и «Открыть» работают для user-id

## Фаза C6 — Смена портрета на листе (опционально, но желательно)

**Промпт:**
> Дай менять портрет уже на странице персонажа (user-карточки only):
> 1. На `.portrait-frame` — кнопка «Сменить фото» (только если `char.isUser`).
> 2. Тот же лимит 2 МБ / сжатие до 800px, та же подсказка 600×800 3∶4.
> 3. Обновить `portrait` в `gob-user-characters` + `#char-img` src.
> 4. Touch target ≥ 44px; на mobile — bottom sheet или нативный file picker.

**Критерии готовности:**
- [ ] Портрет меняется без пересоздания персонажа
- [ ] На главной после reload карточка показывает новое фото
- [ ] Встроенные герои без кнопки смены (статичные jpg)

---

## Фаза C7 — Удаление и устойчивость (опционально)

**Промпт:**
> Завершающий pass:
> 1. На листе user-персонажа — «Удалить карточку» (confirm) → убрать из `gob-user-characters`, удалить `gob-sheet-{id}`, редирект на `/`.
> 2. Quota guard: если `localStorage` переполнен — сообщение «Слишком большое фото, выберите файл меньше».
> 3. Миграция: если в sheet есть `name`, а в каталоге пусто — однократный sync при load.
> 4. Документировать лимиты в комментарии в `gob-characters.js`.

**Критерии готовности:**
- [ ] Удаление user-карточки не трогает встроенных
- [ ] Нет silent fail при переполнении storage
- [ ] Smoke: create пустой → лист → главная → открыть → удалить

## Быстрые правила для всех фаз

- Ветка: `create-hero` → merge в `develop` после закрытия C1–C5 (минимум).
- Коммиты: `feat(create): C{n} …` / `fix(create): …`
- Не добавлять React/Vue; не трогать игровые формулы листа.
- Портрет встроенных героев — по-прежнему `/characters/{id}.jpg`.
- Пользовательский портрет — data URL в `gob-user-characters` (до появления server upload).
- Каждая фаза — smoke: create (пустой / с фото) → лист → главная → открыть карточку.
- `prefers-reduced-motion` — без лишних анимаций на create; переходы через `GobMotion`.

## Порядок выполнения

```
C1 → C2 → C3 → C4 → C5 → (C6) → (C7)
```

C6–C7 можно отложить, если нужен быстрый MVP: **C1–C5** дают полный цикл «создать (в т.ч. пустую) → играть листом → видеть в карусели».

## Smoke-сценарии (приёмка)

1. **Пустая карточка:** Create → «Пустая карточка» → лист с заглушкой → имя/описание пустые → заполнить на листе → главная показывает обновлённые данные.
2. **С фото:** загрузить 600×800 → create → портрет на листе и в карусели.
3. **Только имя:** описание и фото пустые → имя на обороте карточки.
4. **Регрессия:** Evade (001) и остальные встроенные — без изменений.
