# Кнопка «получить пизды» — авторасчёт входящего урона

**Ветка:** `feature/damage-intake` (от `develop`, merge в `develop`)
**Цель:** на листе персонажа есть кнопка, запускающая пошаговый визард списания
входящего урона (урон → уворот → щиты → бабл → плоская броня → HP), который считает
итог по защитным агрегатам листа и применяет результат к текущим HP.
**Источник спецификации:** [TO-DO.md](TO-DO.md) → «Кнопка „получить пизды“» (С2·3);
доменный порядок поглощения — вики «Боевая система (GoB)» (Баблы → Защита → HP).

Каждая фаза — отдельная сессия работы. Выполнять по порядку.

## Принципы

- **Порядок шагов — как в спецификации С2·3:** урон → уворот → щит(ы) → бабл → плоская
  броня → HP. Уворот и щит — *активные проверки* (снижают урон только при успехе); бабл
  обнуляет урон целиком, пока активен; броня вычитается плоско.
- **Считаем из существующих агрегатов, не заводим новые боевые поля.** Уворот =
  `evasion`, Защита = `armor`, Баблы = `bubble` (класс + снаряга + кастом-источники),
  щиты = `shieldGuard` по рукам (`shieldRowValue`). Итог применяется к `sheet.combat.hp`.
- **Игровые формулы листа не менять** (`maxHp = str×4 + hpBonus` и т. п.). Визард только
  *читает* агрегаты и пишет `hp`/`bubbleActive`, не переопределяет производные показатели.
- **Логика расчёта — чистая функция** (без DOM), UI — поверх неё. Так шаги проверяемы и
  переиспользуемы для будущего «боевого стола» ([TO-DO.md](TO-DO.md), «Стол файта»).
- **Два щита = две отдельные проверки** (см. [BUGS.md](BUGS.md) B4). Щиты пассивной
  защиты не дают — шаг щита появляется только при надетом щите в руке.
- **Бабл — по модели листа.** Пока активен (`bubbleActive !== false`, единиц > 0) —
  входящий урон 0. «Упал» → `bubbleActive = false`; «выстоял» → −1 единица (через
  системный кастом-источник строки `combat-row-bubble`, чтобы развёртка осталась
  консистентной и правка сохранилась).
- **ГМ как владелец** работает без спецкода: визард пишет через тот же `scheduleSave`,
  правка уезжает в хранилище владельца и рассылается по SSE.
- Не переписывать на React/Vue; ванильные `GobXxx`-модули, нативный `<dialog>` как у
  `effect-modal`/`quest-modal`. Desktop не ломать; на телефоне визард юзабелен.

## Модель данных (что читаем/пишем)

| Шаг | Источник значения (чтение) | Эффект (запись) |
|---|---|---|
| Урон | — (ввод игрока) | — |
| Уворот | `evasion` = `sumEquipmentMods().evasion + dexClassEvasion() + custom` | урон −= уворот (если проверка успешна) |
| Щит Л/П | `shieldRowValue('leftHand'/'rightHand')` (только если надет щит) | урон −= щит (если проверка успешна) |
| Бабл | `bubble` = `spiClassBubble() + snaряга + custom`, `sheet.combat.bubbleActive` | урон = 0; «упал» → `bubbleActive=false`, «выстоял» → −1 ед. |
| Броня | `armor` = `sumEquipmentMods().armor + endClassArmor() + custom` | урон −= броня (плоско) |
| Итог | `sheet.combat.hp` | `hp = max(0, hp − max(0, урон))` |

Новых полей в `sheet` не вводим. Декремент бабла хранится как системный источник
`{ sys: 'bubbleSpend', label: 'Пробитие бабла', value: −N }` в
`sheet.combatCustom['combat-row-bubble']` — уже поддерживаемая инфраструктура
(`customSourceEntries`/`customSourcesSum`).

## Smoke-сценарии (приёмка)

1. **Голый урон.** Персонаж без брони/уворота/щита/бабла: урон 10 → уворот «не прошёл» →
   броня 0 → HP −10.
2. **Уворот + броня.** Уворот 3 «прошёл», Защита 2: урон 10 → −3 (уворот) → −2 (броня) →
   HP −5.
3. **Щит в руке.** Надет щит Т1 (3) в левую: урон 10, уворот «не прошёл», щит «прошёл» →
   HP −7; два щита → две отдельные проверки.
4. **Активный бабл.** Бабл активен (единиц ≥ 1): любой урон → HP 0; «упал» → строка «Баблы»
   Выключен; «выстоял» → единиц −1, HP не изменился.
5. **Регрессия.** Ручная правка HP, счётчик/переключатель бабла, строки Уворот/Защита/Щит и
   их развёртки работают как прежде; `npm test` зелёный.
