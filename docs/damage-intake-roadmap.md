# Кнопка «получить пизды» — авторасчёт входящего урона

**Ветка:** `feature/damage-intake` (от `develop`, merge в `develop`)
**Цель:** на листе персонажа есть кнопка, запускающая пошаговый визард списания
входящего урона (урон → уворот → щиты → бабл → плоская броня → HP), который считает
итог по защитным агрегатам листа и применяет результат к текущим HP.
**Источник спецификации:** [TO-DO.md](TO-DO.md) → «Кнопка „получить пизды“» (С2·3);
доменный порядок поглощения — вики «Боевая система (GoB)» (Баблы → Защита → HP).

Каждая фаза — отдельная сессия работы. Выполнять по порядку.

## Принципы

- **Порядок шагов — как в спецификации С2·3:** урон → уворот → щит(ы) → бабл → плоская
  броня → HP. Уворот и щит — *активные проверки* (снижают урон только при успехе); бабл
  обнуляет урон целиком, пока активен; броня вычитается плоско.
- **Считаем из существующих агрегатов, не заводим новые боевые поля.** Уворот =
  `evasion`, Защита = `armor`, Баблы = `bubble` (класс + снаряга + кастом-источники),
  щиты = `shieldGuard` по рукам (`shieldRowValue`). Итог применяется к `sheet.combat.hp`.
- **Игровые формулы листа не менять** (`maxHp = str×4 + hpBonus` и т. п.). Визард только
  *читает* агрегаты и пишет `hp`/`bubbleActive`, не переопределяет производные показатели.
- **Логика расчёта — чистая функция** (без DOM), UI — поверх неё. Так шаги проверяемы и
  переиспользуемы для будущего «боевого стола» ([TO-DO.md](TO-DO.md), «Стол файта»).
- **Два щита = две отдельные проверки** (см. [BUGS.md](BUGS.md) B4). Щиты пассивной
  защиты не дают — шаг щита появляется только при надетом щите в руке.
- **Бабл — по модели листа.** Пока активен (`bubbleActive !== false`, единиц > 0) —
  входящий урон 0. «Упал» → `bubbleActive = false`; «выстоял» → −1 единица (через
  системный кастом-источник строки `combat-row-bubble`, чтобы развёртка осталась
  консистентной и правка сохранилась).
- **ГМ как владелец** работает без спецкода: визард пишет через тот же `scheduleSave`,
  правка уезжает в хранилище владельца и рассылается по SSE.
- Не переписывать на React/Vue; ванильные `GobXxx`-модули, нативный `<dialog>` как у
  `effect-modal`/`quest-modal`. Desktop не ломать; на телефоне визард юзабелен.

## Модель данных (что читаем/пишем)

| Шаг | Источник значения (чтение) | Эффект (запись) |
|---|---|---|
| Урон | — (ввод игрока) | — |
| Уворот | `evasion` = `sumEquipmentMods().evasion + dexClassEvasion() + custom` | урон −= уворот (если проверка успешна) |
| Щит Л/П | `shieldRowValue('leftHand'/'rightHand')` (только если надет щит) | урон −= щит (если проверка успешна) |
| Бабл | `bubble` = `spiClassBubble() + snaряга + custom`, `sheet.combat.bubbleActive` | урон = 0; «упал» → `bubbleActive=false`, «выстоял» → −1 ед. |
| Броня | `armor` = `sumEquipmentMods().armor + endClassArmor() + custom` | урон −= броня (плоско) |
| Итог | `sheet.combat.hp` | `hp = max(0, hp − max(0, урон))` |

Новых полей в `sheet` не вводим. Декремент бабла хранится как системный источник
`{ sys: 'bubbleSpend', label: 'Пробитие бабла', value: −N }` в
`sheet.combatCustom['combat-row-bubble']` — уже поддерживаемая инфраструктура
(`customSourceEntries`/`customSourcesSum`).

## Фаза D5 — Контестная модель: противоудар, криты, бабл-D10 (✅ готово)

Ревизия по уточнению домена: уворот и щит — **встречный бросок** против одного броска
попадания атаки (у кого больше — тот прав, при равенстве прав защитник). Криты/антикрит
защитника считаются авто по стату «Крит» листа и размеру кубика.

**Модель (реализовано):**
- **Стр. урона:** урон + **бросок попадания атаки** (один, общий) + **селектор кубика**
  (D6/D12/D20/D60/D100) + **галка «крит атаки»** (крит атакующего — только вручную).
- **Крит защитника** = бросок ≥ `max(2, N − Крит)`; **антикрит** = чистая 1 (считается авто).
- **Уворот** — по таблице боевой системы: крит бьёт некрит; оба крит → урон ×2 и уворот ×2,
  сравниваем броски; **антикрит защитника → урон ×2**, уворот не применяется; крит-уворот vs
  не-крит атака → урон 0 + **«Рипост!»** (контратака — вне списания HP). Удвоение урона живёт
  только на шаге уворота (один раз на атаку).
- **Щит** — встречный бросок vs той же атаки: **крит щита → блок ×2** значения независимо от
  крита атаки; без крита щита **крит атаки пробивает** щит; иначе у кого бросок больше — тот
  прав (равенство — защитнику). Антикрит на щите = просто проигрыш броска.
- **Бабл** — пока активен, урон 0; бросок **D10** как проверка от 1 до текущих единиц: успех
  (≤ единиц) → держит удар, **−1 ед., но не ниже 1**; провал → **сбит** (`bubbleActive=false`).
- Формулировки на шагах: **«не увернулся»** / **«не защитился»**.

**Промпт:**
> 1. Переписать `computeDamageIntake` на контестный редьюсер: вход
>    `{ raw, atkRoll, atkCrit, die, defCrit, dodge:{value,roll}, shields:[{value,roll}],
>    bubble:{active,units,roll}, armor }`; вернуть `{ steps, finalDamage, riposte, bubble }`.
> 2. `openDamageWizard`/`damageIntakeInput` — снимок `die=HIT_DICE[0]`, `defCrit=effectiveCrit()`,
>    поля бросков вместо `passed`. Стр. урона — селектор кубика, бросок атаки, галка крита.
> 3. Заменить да/нет на `renderDamageContestStep` (бросок защиты + живой вердикт из
>    `currentComputeStep`); бабл — ввод D10; `spendBubbleUnit` с полом на 1; `applyDamageIntake`
>    по `result.bubble` (успех → −1, провал → выключить).
> 4. Стили: `.damage-atk-row/.damage-field/.damage-select/.damage-num/.damage-check/.damage-verdict`.

**Критерии готовности:**
- [x] Один бросок атаки на странице урона; уворот и щиты сверяются с ним.
- [x] Крит/антикрит защитника считаются авто по кубику и стату «Крит»; таблица уворота
      (крит/оба крит/антикрит/рипост) даёт верные числа.
- [x] Щит: крит → блок ×2; крит атаки пробивает; ничья — защитнику.
- [x] Бабл: D10-проверка, −1 не ниже 1, провал → выключение; урон 0 пока активен.
- [x] `node --check` чистый; `npm test` — 71/71; сквозной прогон в браузере без ошибок консоли.

## Фаза D6 — UX-правки по фидбеку (✅ готово)

Точечные правки контестной модели по замечаниям игрока (механика не менялась, только ввод/подача):

- **Крит атаки урон не удваивает.** Удвоение кубов уже вписано игроком в поле урона, поэтому
  галка «Крит» влияет **только на исход контеста** (пробитие щита, сравнение бросков, уворот ×2
  при обоюдном крите), а не на само число урона. Убрано `before×2` на шаге уворота для
  `atkCrit && !defCrit` и множитель урона в ветке обоюдного крита (удваивается лишь уворот).
- **Кубик запоминается.** Последний выбранный кубик хранится в `localStorage['gob-damage-die']`
  (`lastDamageDie`/`rememberDamageDie`) и подставляется при открытии визарда.
- **Галка «Крит»** переименована из «Крит атаки», переведена в общий стиль листа
  (`accent-color: var(--gold-dark)`, 20px) и вынесена в одну строку с кубиком и броском атаки
  (`.damage-field--check` внутри `.damage-atk-row`).
- **«+ рипост»** убран из надписи на крит-уворотe и из итоговой сводки (сам исход «урон 0»
  остаётся; `riposte` по-прежнему считается, но не выводится).
- **Возвращены кнопки ручного выбора** «Увернулся/Не увернулся» и «Защитился/Не защитился» —
  над разделителем, бросок защиты — под ним. Способы взаимоисключающие: клик по кнопке гасит
  бросок, ввод броска снимает ручной выбор. В редьюсере — приоритетная ветка `manual: pass|fail`.

**Критерии готовности:**

- [x] Кнопки ручного выбора работают и взаимоисключаются с броском защиты.

## Smoke-сценарии (приёмка, контестная модель D5)

1. **Уворот выигрывает.** Урон 10, атака бросок 3 (D6, не крит), уворот 3, бросок защиты 3
   (ничья → защитник) → «увернулся −3» → HP −7.
2. **Уворот проигрывает.** То же, бросок защиты 2 → «не увернулся» → HP −10.
3. **Крит атаки.** Урон 10, галка «крит атаки», уворот не крит → «крит атаки — урон ×2» →
   HP −20.
4. **Крит-уворот.** Атака не крит, бросок уворота в крит-диапазоне (D6, Крит 2 → ≥4) →
   урон 0 + «Рипост!».
5. **Щит.** Щит Т1 (3) в левой: крит щита → блок ×2 (−6); крит атаки без крита щита → пробил;
   иначе бросок ≥ атаки → −3.
