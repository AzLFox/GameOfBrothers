# Баг B4 — щит: активная проверка вместо пассивной защиты

**Ветка:** `fix/b4-shield-active-guard` (от `develop`, merge в `develop`)
**Цель:** значение щита больше не вливается в пассивную боевую строку «Защита»; щит
получает собственный показатель `Щит` (активная проверка при получении урона), а
латная броня (наручи, класс END) остаётся пассивной без изменений.

Каждая фаза — отдельная сессия работы. Выполнять по порядку.

## Причина (по коду)

- Класс `shield` ([../public/js/item-catalog.js:89](../public/js/item-catalog.js#L89)) отдаёт
  модификатор `armor` (`type: 'flat'`, [:34](../public/js/item-catalog.js#L34)).
- `sumEquipmentMods()` ([../public/js/character.js:709](../public/js/character.js#L709)) суммирует
  **все** `flat`-модификаторы надетых предметов, поэтому `armor` щита попадает в агрегат и
  рисуется в строке «Защита» (`renderExtraCombatRows` [:911](../public/js/character.js#L911)) —
  щит работает как пассивная броня.
- Тот же ключ `armor` используют латные наручи `bracers_plate`
  ([../public/js/item-catalog.js:132](../public/js/item-catalog.js#L132)) и классовая броня END
  (`endClassArmor` [../public/js/character.js:278](../public/js/character.js#L278)) — это **настоящая**
  пассивная защита, её трогать нельзя. Значит, отделять нужно именно вклад щита, а не весь `armor`.

## Принципы

- **Разделяем по модификатору, а не спецкейсами.** Щит получает собственный ключ модификатора
  `shieldGuard` (label «Щит»); `armor` остаётся только у настоящей пассивной брони. Тогда агрегат
  «Защита» перестаёт видеть щит без каких-либо `if (family === 'shield')` в коде суммирования.
- **Латную броню не трогаем.** `bracers_plate`, `endClassArmor` и строка «Защита» работают как
  прежде.
- **Игровые формулы листа не менять** (`maxHp = str×4 + hpBonus` и т. п.); фронтенд без сборки,
  ванильные `GobXxx` — не переписывать на React/Vue.
- **Обратная совместимость сохранённых листов.** У уже сохранённых щитов `mods: { armor: N }`
  зашит в предмете (localStorage / серверный JSON / файл экспорта). Нужна миграция ключа при
  загрузке — иначе старый щит продолжит вливаться в «Защиту». Миграция обязана покрыть все точки
  входа предметов: снаряжение, рюкзак, импорт.
- **Активный расчёт входящего урона — вне этого фикса.** Кнопка «получить пизды» (шаг «Щит в
  руке», [TO-DO.md](TO-DO.md), С2·3) — отдельная задача; она будет читать значения щитов через
  `equipmentModSources('shieldGuard')`. Здесь мы только убираем пассивность и выводим показатель.

## Модель данных (что меняется)

| Было (щит) | Стало (щит) |
|---|---|
| `mods: ['armor']`, тиры `{ armor: 3/6/9/12 }` | `mods: ['shieldGuard']`, тиры `{ shieldGuard: 3/6/9/12 }` |
| вклад в **общий агрегат** `armor` → строка «Защита» | **по строке на каждый надетый щит** → «Щит в левой/правой руке» |

Новый модификатор: `shieldGuard: { label: 'Щит', type: 'flat', combat: 'row' }`. Но щит **не
агрегируется** в одну строку: как урон у оружия, щитов может быть два и каждый — отдельная
проверка. Поэтому вместо суммарной строки «Щит» рисуется **по строке на каждый надетый щит** с
подписью по руке: «Щит в левой руке» / «Щит в правой руке». Строки появляются только при надетом
щите (у `shieldGuard` нет записи в `CLASS_ROW_STAT`).
