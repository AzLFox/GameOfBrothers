# Баг B2 — аккаунт ГМ показывать как «Аккаунт мастера», а не «Аккаунт игрока»

**Ветка:** `fix/b2-gm-account-label` (от `develop`, merge в `develop`)
**Цель:** в списке аккаунтов при формировании группы аккаунт с ролью `gamemaster`
подписан «Аккаунт мастера» и визуально отличается, вместо ошибочного «Аккаунт игрока».

Каждая фаза — отдельная сессия работы. Выполнять по порядку.

## Причина (по коду)

- `GET /api/group/accounts` ([../server/server.js:605](../server/server.js#L605)) отдаёт
  `{ id, username, kind, isSelf }` — **без `role`**, поэтому фронтенд не знает, что аккаунт мастерский.
- `accountCard()` ([../public/js/group.js:390](../public/js/group.js#L390)) подписывает карточку
  «Ваш аккаунт» (self) либо «Аккаунт игрока» (все прочие) — **ветки для ГМ нет**.

Авторитетный источник роли уже есть — `auth.resolveUserRole(user)` ([../server/auth.js:130](../server/auth.js#L130)),
им же формируется `publicUser`. Достаточно прокинуть роль в список аккаунтов и добавить ветку в UI.

## Принципы

- Правка только точки отображения роли (B2 — про подпись, не про фильтрацию): состав списка
  аккаунтов и логику приглашений не менять. Скрытие ГМ из списка приглашаемых — отдельная тема
  ([TO-DO.md](TO-DO.md), «явный элемент ГМ в модели группы»), в этот фикс не входит.
- Роль резолвить на сервере через `auth.resolveUserRole` — не дублировать логику env
  `GOB_GM_USERNAMES` на фронте.
- Фронтенд без сборки, ванильные `GobXxx`; не переписывать на React/Vue; игровые формулы листа не трогать.
- Обратная совместимость: если `role` в ответе нет (старый сервер) — карточка деградирует к
  «Аккаунт игрока», не падает.

## Фаза B2-2 — Фронтенд подписывает и выделяет мастера (✅ готово)

**Промпт:**
> 1. В `accountCard()` ([../public/js/group.js:390](../public/js/group.js#L390)) ввести
>    `const isGm = account.role === 'gamemaster';`. Порядок подписи: `isSelf` → «Ваш аккаунт»,
>    иначе `isGm` → «Аккаунт мастера», иначе «Аккаунт игрока».
> 2. Навесить классы-модификаторы: на карточку `group-account-card--gm`, на `<p>` подписи
>    `group-account-meta--gm` — при `isGm`.
> 3. В [public/css/group.css](../public/css/group.css) добавить стили `--gm`: подпись золотым
>    акцентом (`--gold`/`--gold-light`), тонкая рамка карточки — чтобы мастер визуально отличался.

**Критерии готовности:**
- [x] Мастерский аккаунт в списке приглашения подписан «Аккаунт мастера» и визуально выделен.
- [x] Обычный игрок по-прежнему «Аккаунт игрока»; свой аккаунт (если показан) — «Ваш аккаунт».
- [x] Без `role` в ответе карточка не падает и деградирует к «Аккаунт игрока».

**Реализовано:** ветка `isGm` в `accountCard()` + классы `--gm`
([../public/js/group.js:390](../public/js/group.js#L390)); стили
`.group-account-card--gm`/`.group-account-meta--gm` в [../public/css/group.css](../public/css/group.css).
Smoke: подпись «Аккаунт мастера», цвет `--gold-light`, рамка `--gm` подтверждены в браузере.
